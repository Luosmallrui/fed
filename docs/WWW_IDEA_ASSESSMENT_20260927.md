# WWW 投稿潜力评估（2026-09-27）

**结论：方向可以投 WWW；当前版本不建议直接作为主会方法论文投稿。** 建议保留通信压缩问题与实验平台，重新确立能被证据支持的核心贡献。当前就绪度低，发展潜力中等；推荐为 `pivot-with-rescue-route`，不是放弃方向。

本次按 WWW 2027 Research Track 的长文目标评估目录里的“预训练谱固定 A + B-only 联邦微调 + 双向 Top-k / error feedback（EF）+ 精确序列化字节预算”。这是 idea 与方法证据评估，不涉及重写论文。根目录旧稿的 Qwen / Banking77 数字未作为当前结果依据。

**会议范围与时间。** WWW 2027 官方要求第一页明确 Web 和 track 相关性，仅使用 Web 数据集不足以构成相关性。可考虑 Web Infrastructure and Agentic Systems；检索、推荐和个性化是其他可选落地场景，并非强制任务。摘要截止 2026-10-18，全文截止 2026-10-25，均为 AoE。[官方 CFP](https://www2027.thewebconf.org/research-track-papers/)

**检索状态：已做针对性近邻检索，覆盖仍属部分。** 核验了公开论文、作者实现和会议官网；未进行系统综述或复现外部方法。当前不就绪的判断置信度较高；任何新救援路线的创新性置信度仅中等，需要再次检索和验证。

**问题与方法归一化。** 问题是非 IID 联邦微调中适配器的双向通信成本；困难是固定字节预算下，同时保留任务适应能力和更新信息。原始假设是固定共享 A 可保持线性聚合坐标，预训练主右奇异子空间比匹配随机子空间更适合适配，再用 EF 补偿稀疏损失。方法确实可实现，但“预训练权重能量大”不能直接推出“下游任务需要该方向”。决定性证据应同时分离子空间选择、压缩、EF、优化和真实通信成本。

**最近工作与剩余差异。** 表中风险指当前创新叙述受到的威胁，不表示两种算法完全相同。

| 近邻工作与已核验年份/来源 | 已有内容 | 当前剩余差异与风险 | 需要证明的区分 |
|---|---|---|---|
| [FFA-LoRA，ICLR 2024](https://arxiv.org/abs/2403.12313) | 固定随机 A，只训练 B，减少联邦因子聚合问题和通信 | 当前改为谱/正交随机基，并叠加稀疏 EF；高 | 谱基或压缩耦合带来什么固定随机 A 无法实现的结果 |
| [FLASC，2024 预印本](https://arxiv.org/abs/2406.05233) | 完整 LoRA 本地训练，通信时稀疏化 | 当前提供 EF、固定子空间和更严格字节口径；高 | 同预算、清楚模型状态语义下的额外收益 |
| [STC，TNNLS 2020](https://ieeexplore.ieee.org/document/8889996) | 一般 FL 的上下行压缩；其算法包含两端误差累积 | EF 迁移到 LoRA 不足以单独成为新机制；高 | LoRA 特有的误差结构、适用条件或新能力 |
| [LoRA-XS，2024 预印本，2025 修订](https://arxiv.org/abs/2405.17604) | 冻结预训练 SVD 因子，训练小 core | 当前只固定输入侧、训练 B 并结合 FL 稀疏传输；中高 | 为什么该参数化比固定双侧或随机单侧更适合目标约束 |
| [FedSRD，WWW 2026](https://arxiv.org/html/2510.04601v3) | 稀疏上传、重构聚合、稀疏下发；讨论分解旋转导致差分不稳定 | 当前采用长期固定基与 EF，不能只以双向压缩或坐标稳定区分；高 | 与 FedSRD/FedSRD-e 对照，说明表达能力、压缩失真和成本的实质差异 |
| [EcoLoRA，EMNLP 2025](https://aclanthology.org/2025.emnlp-main.1046/) | 分段轮换共享、自适应稀疏化和无损编码 | 当前是固定子空间和 EF 路线；中 | 将编码开销计入后，是否仍有可解释的质量—通信优势 |
| [TRISHUL，2026-07 预印本](https://arxiv.org/abs/2607.20914) | 共享冻结低秩基、core 聚合和谱控制 | “共享谱基改善联邦稳定性”已有近邻；中高 | 具体谱选择准则与稀疏误差机制，而非宽泛谱稳定性主张 |
| [Adaptive Phase-Switching，2026-09 预印本](https://arxiv.org/abs/2609.13512) | 自适应切换聚合阶段、B-only 通信及双向字节核算 | 影响“先学 A 再冻结”的潜在救援路线；中 | 不能把阶段切换或字节核算本身当作新发现 |

FedSRD 在 [WWW 2026 官方日程](https://www2026.thewebconf.org/program/full-schedule.html) 中列于 Systems 2 的联邦学习主题。因此，大方向有同会先例。当前不足在于相对近邻工作的贡献和 Web 问题证据，而非“WWW 不收联邦学习”。

补充核对：Full-LoRA EF 与 no-EF 的 18 对在 CSV 中模型、数据、划分、布局、初始化、轮数、学习率、delivered bytes 均匹配，最终指标为 16 对提升、2 对下降。六个 task/budget 平均增量依次为 SST-2 +0.125765/+0.066131，RTE +0.068592/+0.080626，MNLI +0.067189/+0.032203。不过执行源码不同，归档的 [SOURCE_DELTA](results/full_lora_noef/formal/provenance/SOURCE_DELTA.md) 已标明 cross-source / post-hoc，故这里只作为描述性补充，不升级成新盲确认或严格同源码因果证据。独立 no-EF 报告的“0 paired”也不能读成真实的“0 次达到目标”。

MNLI 的 dense seed403 接近随机水平，会影响均值和相对 dense 的目标阈值；应保留全部 seed 并报告敏感性分析。现有 FLASC-style 使用受控优化器和 masked-server 指标，不能直接把与 communicated-global 模型的数值差当成同状态机制收益。MRPC/QQP 的 V4 结果是 train-holdout 开发证据；被隔离的 task-suite 部分运行不能充当正式确认。

**三个决定性阻碍及修复条件。**

1. **高严重度，核心贡献需要重构。** 固定 A、谱参数化、稀疏通信和双向 EF 各有先例；现有结果支持最强的部分又主要是已知 EF。修复需要一个超出组合的规律或机制，并与 FedSRD(-e)、FFA-LoRA、FLASC 等建立清楚区分。仅增加 GLUE 数据集或改标题不能消除该风险。
2. **高严重度，原始科学假设尚未成立。** Spectral-A 的优势条件不稳定。固定 A 能让聚合线性化，却不保证更好的适配空间。Full-LoRA 参数空间 EF 仍是定义良好的算法，不能因存在等价分解就断言其残差无意义。修复条件是量化并预测固定子空间的收益边界，在未参与选择的设置上确认。
3. **高严重度，Web 问题与证据链不足。** RoBERTa/GLUE 可以检验算法局部性质，但当前未充分展示其解决何种 Web 服务约束。可在跨站点/跨机构服务模型协同适配中落实异质数据和带宽约束；如选择搜索、推荐或内容理解，需用对应任务目标和指标。修复需要真实的问题定义和证据，不是增加“面向 Web”措辞。

工程实现本身没有发现使整条方法必然无效的错误。精确字节统计、匹配消融、保留失败结果是可复用的基础。基线异常、评价状态和新旧报告不同步属于可修复的证据问题；它们需要解决，但解决后也不会自动补足创新。

**最小救援路径。** 保留现有平台，先研究一个可证伪问题：在相同序列化字节预算下，固定子空间的任务表达损失，是否会抵消它在压缩与聚合上的收益？谱能量是否只是较差的选择指标？这目前是候选问题，不是已证明的新发现。

对于行正交 A，令 P=AᵀA，则可表示的局部更新位于右投影空间；任务更新 G 的被排除部分为 G(I−P)。同时 B 的误差 E 满足 ‖EA‖F=‖E‖F（有效权重误差还需计入 LoRA 缩放系数）。这说明“保留什么任务方向”与“坐标里多容易稀疏化”可以分开检验；这些基本代数关系自身不足以成为独立创新。

最有价值的下一步证据是：利用已有 dense/no-EF/EF 对照先判定主要损失来源，再以任务更新对齐和相同更新的压缩回放检验解释是否成立。旋转实验需控制 AdamW 的坐标敏感性，否则无法把变化单独归因于 Top-k。只有解释能预测未见设置，才值得从中设计新规则并扩展至目标 Web 场景。若只是重复发现 EF 有益，当前成果更适合作为受控实证结果继续积累，不能据此宣称已具备 WWW 主会方法贡献。

**本次完成范围。** 已核验当前方法定义、主要结果及补充实验状态、最近工作、2027 官方范围与日期，并区分开发/正式/post-hoc 证据。没有运行新实验、修改方法、替换任务或重写稿件；没有启动其他研究模块。未完成的是外部基线复现、完整逐轮数据审计以及新路线的创新确认，这些限制不改变当前“不宜直接投主会”的建议。
